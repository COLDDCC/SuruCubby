# SuruCubby · 群友电子仓库

当前流程：日本订单 Excel → 客户仓库 → 拆包/合包并填写回国单号 → 称重（逐件或整摞）、确认运费 → 绿色「可发货」 → 客户选商品和地址申请发货 → 群主核对扫码转账 → 填写国内快递单号寄出。

## 本次更新与使用规则

- 一张 Excel 按一个日本订单导入；数量拆成独立商品，支持任意购物网站的链接。表头至少有「名称」「客户名字/cn」。
- 「应付日元金额」是**整行日元总额**，按数量拆分且保持总额不变；没有这一列时按「实际价格 × 数量」记货款。**货款一律是日元，不折人民币**——汇率波动大，预先折算等于群主替客户吃差价；客户付款当天自己按汇率扫码转账。人民币只出现在国际运费、国内运费上。
- 表头写着「数量」但那一列的数全都大于 10 时（骏河屋的表常这样，那其实是平时价格），整批会被拦下来：在导入预览的「列对应关系」里把这列改成「平时价格」即可，数量按 1 件算。
- 日本订单号、日本物流单号在导入页或批次详情录入。回国单号属于包裹，客户看到自己商品关联的单号，可复制到微信查询。
- 包裹详情勾选商品可移动到另一个未计费包裹或新建包裹，实现拆单/合单。已计费、已申请、已寄出商品不能直接移动，防止账目关联错误。
- 称重台可以逐件填克数，也可以一整摞只填一个总重（摞内按件数均摊）；整箱到齐时点「整箱全部认领」一次归好。没收到的商品必须明确标为缺件。**分摊可以一摞一摞分批做**：谁称好了就先算谁、谁先变成绿色「可发货」，不必等全箱几十个人。每次确认只有那几摞进账，包裹的总运费是历次累加。状态key仍是 `cn_stock`，只是显示名从「已到国内」改成「可发货」。
- 自己带回国 / 另找转运的客户可以在客户详情页或称重台标成**不拼邮**（`customers.self_return`，迁移 `0007`，默认拼邮）。标了之后认领、称重、国际运费分摊、发货申请、国内寄出这一整条链都不算他，「整箱弄完了」也不再被他卡住；**货款照旧按导入表记，一分不动**。已有运费账目、未处理完的申请或寄出记录时会被拦住，要先撤销；只认领没算费的会自动退回未认领。当面把货交给他之后，客户详情页点「这几件已经当面给他了」就整批标「已签收」，不生成寄出也不收国内运费。
- 客户最多保存3个地址（删除后可重新添加），勾选绿色商品并选择地址提交申请；申请保存当时地址副本。
- 按选中商品收国际运费，每次申请国内运费使用后台设置（默认10元）；线上不接支付。群主在「发货申请」核对扫码转账后确认收款，再填写单号寄出。
- 收款错误可在收款记录撤销；国内申请款撤销后退回待收款，国际款撤销后必须重新确认收款才能寄出。已寄出的申请保留历史，不允许直接撤销物流。
- 合并客户：有冲突的已计费称重组时禁止合并，先撤销相关收款和分摊。其他未计费数据可合并；地址合计超过3个时先整理地址。
- 后台导航「订单」（原「批次」）列出录入过的每一个日本订单：日本订单号 / 物流单号填没填、几个人几件、各状态件数和进度条、货款收齐没有、装进了哪个包裹。可按订单号、物流单号、订单名、客户名、包裹名搜索，按「进行中 / 已完结 / 货款没收齐 / 单号没填」筛选（筛选会记在本机浏览器）。订单详情里把单号删空提交就是清掉。
- 修改管理员密码会让旧管理员登录失效。后台密码输错5次锁15分钟；写操作串行保护，多窗口同时保存时提示重试。

## 技术栈

| 部分       | 选择                                                    |
| ---------- | ------------------------------------------------------- |
| 运行环境   | Cloudflare Workers + 静态资源                           |
| 后端       | Hono                                                    |
| 数据库     | Cloudflare D1（SQLite）                                 |
| Excel 解析 | 浏览器端 SheetJS，解析成 JSON 再提交，Worker 不碰二进制 |
| 前端       | 原生 HTML/ES Module，手机优先，无构建步骤               |

硬性约定：**金额一律用整数「分」存**，日元用整数「円」存；时间存 UTC，页面按北京时间显示。

## 本地跑起来

```bash
npm install
cp .dev.vars.example .dev.vars     # 填上 ADMIN_PASSWORD 和 SESSION_SECRET
npm run db:local                   # 建本地库表
npm run dev                        # http://127.0.0.1:8787
```

打开 <http://127.0.0.1:8787/admin/>，用 `.dev.vars` 里的密码登录。

## 部署到 Cloudflare

```bash
npm install
npx wrangler login                          # 浏览器里授权一次 Cloudflare 账号

npx wrangler d1 create surucubby            # 把返回的 database_id 填进 wrangler.toml
npm run db:remote                           # 在线上库建表
npm run deploy                              # 先部署，Worker 才存在

npx wrangler secret put ADMIN_PASSWORD      # 后台密码
npx wrangler secret put SESSION_SECRET      # Cookie 签名密钥，随便一串长随机字符串
```

密码和密钥设好就立刻生效，不用再 deploy 一次。以后改代码只要 `npm run deploy`。

部署完**务必绑定自己的域名**（Workers 控制台 → 该 Worker → Settings → Domains & Routes）。
`*.workers.dev` 在国内经常打不开。

图片不用另外开图床，默认就能跑，见下面「图片」一节。

可选但国内建议做：把 SheetJS 自托管到 `public/vendor/xlsx.full.min.js`，见 [`public/vendor/README.md`](public/vendor/README.md)。没有这份文件时导入页会回退到官方 CDN。

## 客户怎么登录

**账号就是 QQ 号，密码先统一给 `123456`**，统一入口是 `/login`（手机上直接输 `你的域名/login`，不用群主挨个发链接）；以前发出去的 `/w/{token}` 专属链接照旧能用，两者登进去是同一个人。

- 库里只存 PBKDF2-SHA256 哈希（每人独立随机盐、6 万次迭代），不存明文；`password_hash` 为空就表示这个人还没改过初始密码。
- 用初始密码进来**只看不能动**：存地址、提交发货申请都会被拦下（403，提示先改密码），页面第一屏就是「先改一下密码」。改成自己的之后才正常，旧密码立刻作废。
- 输错 QQ 或密码按 QQ 计数，15 分钟内错 5 次锁 15 分钟（`token_attempts` 表，key 形如 `qq:123456789`）。
- 后期他要改密码：后台 → 客户详情 →「改密码」，可以直接替他设一个（私发给他），留空就是退回初始密码 `123456`，下次他自己进去再改。客户列表里会标「还在用初始密码」，谁没改一眼看得见。
- 登录态是 HttpOnly 签名 Cookie，180 天有效。Cookie 的签名里绑着这个人的密码哈希，所以**改密码（含后台替他改、退回初始密码）会把之前所有浏览器当场踢下线**，必须重新登录；要立刻踢掉还没改密码的人，就在后台点「重置链接」（token 一变，旧链接和旧 Cookie 一起作废）。
- 客户页右上角的「退出登录」只清自己这台浏览器的 Cookie（无状态签名，服务端没有会话表可删），清完这条链接打不开、要重新用 QQ + 密码进；想让别人彻底进不来用上面两条，不是退出。

## 客户页面上看到什么

第一屏就是钱和能发货的东西，往下才是别的：

1. **汇总卡**：货款（円）、运费待付（人民币，为 0 时变绿）、可发货件数。没货可发时这句话会直接说「现在还没有能发的商品」；一件都还没录进来的新客户说「群主还没把你买的东西录进仓库」，两种情况都不会摆一个点不动的按钮骗人。
2. **还穿着初始密码**：横幅卡在汇总卡下面，「先改密码」的按钮就在这张卡上（不是只在报错里提一嘴）。这时候「申请发货」那一栏是**只读**的——后端在这种状态下拦一切写操作，所以页面干脆不给「保存地址」「提交发货申请」这两个必挂的按钮，只写「先把密码改成你自己的」。
3. **可发货**：一件一行的勾选框，和「申请发货」面板贴在一起。勾选状态和页面滚动位置在提交/加地址之后会保留，不会一刷新就得重新勾一遍。
4. **申请发货**：收货地址（最多 3 个，只有一个时自动选中）→ 勾选商品 → 提交。国际运费没付的件会把这一摞的钱摊到每件上显示（`每件之和 = 这一摞 = 这一箱`，和后台分摊同一个口径），已付的摞标「已付」不再重复一个数字。
5. **勾不了的一定写明为什么**：缺件的标「缺件」＋「发货的时候不会带上它」；已经报过申请的标「已申请」；老账里那种只记了整摞运费、没拆到件上的（后端 `POST /requests` 要求件上有 `intl_fee_fen`）不给勾，并写明「在群里说一声，群主重算一次分摊就能勾」。
6. **其余按状态分组**：在日本 / 运输中 / 已寄出-已签收。
7. 寄出记录和回国单号旁的「复制」走 `shared.js` 的 `copyText()`：`navigator.clipboard` 只在 HTTPS / localhost 下有，客户从局域网 http 打开时退回选中复制，再不行提示手动选一下，不会点了就报错。
8. **深色模式是照数字挑的，不是随手配的**：客户手机上的 QQ 浏览器多半跟着系统走深色。状态色（已付绿 / 待付红 / 缺件琥珀）两种模式都要压在最常出现的底色上过 WCAG AA 小字 4.5:1，浅色是 `#0f7a41 / #c92f2f / #96621a`，深色换成 `#5ddc9a / #ff8f8f / #f0c26b`（深底上原来那组只有 2.3~3.6:1，等于看不清）。胶囊底色走同色半透明，危险按钮在深色下改成深墨字。
9. 封面在客户页也是**竖框完整显示**（64×92、`object-fit: contain`），和后台列表一条规矩——裁掉一头就没法对货。手机 ≤480px 时四个数字卡固定两列、字号收一档，免得 `¥12,345.67` 折成两行。
10. 地址打错不再是一片空白：`/login`、`/login/`、`/me`、`/w`、`/w/`、`/w/{任意}` 一律给到客户页，其它未知路径返回一页「找不到这个页面」，写明你输的是什么（转义过）并指向 `/login`。
11. **手机上勾东西时有一条常驻的底部结算条**（`/w` 页最下面）：`已选 N 件 · 合计 ¥X`，小字写清「国际运费 ¥A + 国内运费 ¥B」，右边就是提交按钮，没勾之前是灰的。它只在「有能发的件 + 已经有地址」时出现，初始密码状态下也不出现；带 `env(safe-area-inset-bottom)`，全面屏不会被home 条压住，页面底部跟着留出 Padding，最后一条动态不会被条盖住。
12. 运费那一摞的卡片改成**左标题右数字**一行一项（重量 / 件数 / 这一摞运费），照着竖着加就能对上「件之和 = 这一摞」。

这两条是参考 GitHub 上同类开源项目抄的做法（`rahulupadhyay22/ShipLocker` 的状态胶囊与断点、`rixsoho-ai/fish-groupbuy-order` 的底部 sticky 结算条 + safe-area、`linlinjava/litemall` 移动端的左标题右数字账目行）；本仓库自己没有别人提过外观相关的 issue/PR。

## 日常怎么用

1. **导入**（后台 → 导入）：选 Excel → 填批次名 → 看预览。
   - 表头按文字定位，必须有「名称 / cn」，货款看「应付日元金额」，没有就用「实际价格」；可选「图片 / 商品链接 / 平时价格 / 数量」。猜错的列在预览的「列对应关系」里改，改完会自动重算预览。
   - `cn` 的名字自动认人：写法一模一样直接认；「阿狸 」「Ｍｅｏｗ酱」这种多个空格、全角的，抹平写法差异后只有一个人对得上就认（预览里标「自动对上」，并把这次的写法登记成名字，下次直接中）。归一化之后撞在好几个人身上的不猜，列出候选让你点人；完全没见过的**标黄**，选一个已有客户或填 QQ 新建。黄行没处理完不给导。
   - 认错了人能当场纠正：那一行点「不是这位？改」重新指认，这批货记到你选的人，这个名字也跟着换到他身上（原来那位自动放掉）。
   - 同一个文件（内容哈希相同）导过会提示，勾了确认才放行。
   - 导入时自动建一个同名包裹，这一批的物品都挂在上面，状态 `已下单`。
   - 图片列可以是图片链接，也可以是 `=IMAGE("https://…")` 这种公式（Excel 在线版、飞书表格都会存成公式，见下面「图片」一节）。
   - 新建的客户会把专属链接一次性列出来，复制到群里发给本人；不想发链接就直接甩一句「去 `/login`，账号是你 QQ 号，初始密码 123456，进去先改成自己的」。
2. **客户名单**（后台 → 客户 → 导入名单）：攒了很久的「名字 + QQ 号（+ 真名）」一次灌进来，不用一个个点。表里两列必备（名字、QQ），真名列可有可无；先「看结果」预演（谁新建、谁补名字、谁撞名、哪行 QQ 不像话），确认了才写库。QQ 已存在就不重复建，只把表里的写法补成他的名字、真名空着才填。名字已经属于另一个人的行**一律不动**，列出来让你先去核对，绝不抢别人的名字。真名（`real_name`）只在后台显示和搜索，客户自己的页面拿不到。
3. **改状态**（后台 → 包裹）：下拉改包裹状态，包裹内物品同步变更。
   已取消 / 已退款、以及已经变成「可发货」之后的物品不受影响。
4. **称重**（后台 → 包裹 → 称重台，手机上用）：
   - 顶部常驻「应有 N 件 / 已找到 M 件」「已称 X 人 / 共 Y 人」。
   - 拿起一件点它的封面就算「已找到」；找不到的点「缺件」写说明，缺件不参与分摊。**整箱一次到齐时不用一件件点**：点顶部「整箱全部认领」，剩下的全按「一个客户一摞」归好，还差几件会写在按钮上。
   - 卡片上只留最要紧的两样：**大图 + 货号**（骏河屋商品链接末尾那串编号，点它能打开商品页），对着快递小票核就行。商品名默认不占地方——鼠标停在封面上能看到，碰不到货号（这一件没有商品链接）时才把名字显示出来。
   - 开始称之前，称重台最下面那格先把**这一箱的单价**（元 / kg）填好点「存单价」；默认带出上一次的单价（初始 100 元/kg），涨价跌价直接在这改，不用再跑去「设置」。
   - 每件各自称重：在那一件下面填它的重量（克）。一个人的摞重 = 各件之和。**来不及一件件称也行**：在那一摞右上角填「整摞重量」，这一摞的运费就按件数均摊给里面每件（预览里会写明「整摞均摊」）。两种称法同一摞只认一种：只要还有一件没填重量，就以整摞那个总数为准；已经逐件称齐了再想填整摞会被拦。
   - **称好的那几摞可以先算运费，不用等全箱**（一箱几十个人，等所有人称完谁也发不了货）：点「算分摊」，预览里只有**称好了又还没算过**的那几摞，并写明「这次只算 N 摞，还差 M 摞没称、K 件没认领」；确认后只有这些人变成「可发货」，其余人状态一动不动。这一箱的总运费、总重量按每次分摊**累加**，已算过的那几摞不会再出现在下一次预览里，也不会被算第二遍。
   - 这一箱的运费 = 刚填的单价 × 这次进来那几摞的重量之和，自动算出来不用手填。**手填「实收总额」是转运仓整箱收的那个钱，必须整箱都称完、认领完才让填**（半箱就改，整箱的钱会全压在称好的那几个人头上）；只想先算称好的那几摞就别动金额。可选填转运仓给的总重量对账，同样要整箱弄完才让填。一摞都没称好时点「算分摊」会点名是谁还没称。
   - 已经算过运费的那一摞是**封账**的：改重量、标缺件、取消认领、往那摞里塞新的一件都会被拦（提示「这一摞已经算过运费了」），要改就先「撤销分摊」。撤销是整箱一起退回「回国中」（有人付过运费、申请过发货或已经寄出时会被拦住）。
   - 确认后这些物品立刻变成「可发货」，客户页面当场能勾选申请发货；称重台顶部和包裹详情都会显示「可发货 N 件」，不用去猜。没人付过这个包裹运费之前，可以「撤销分摊」重来（物品退回「回国中」，可发货提示同时消失）。
5. **不拼邮的人**（客户详情页那一行「拼邮」，或称重台每张人卡上的「他不拼邮」）：群里总有人自己带回国、或者另找转运。把这位标成「不拼邮」之后，后面这一整条链都不算他了——
   - **称重台**：一键认领整箱会直接跳过他那几件；单独点他那一件的封面认领、给他填重量（逐件或整摞）都会被拦住，写「这位客户标了不拼邮」。顶部进度变成「应有 N 件 / 共 Y 人」只数拼邮的人，不拼邮的另挂一个灰角标「不拼邮 X 人 / Z 件」，他的那一格只剩一张说明卡。
   - **分摊**：他没有那一摞，所以既不进这次的分摊、也不参与「还差几摞没称」。关键是**这一箱的「整箱弄完了」不再被他卡住**——以前有一个人迟迟不称，别人就永远填不了「实收总额」对账；标掉他之后剩下的人称完就能整箱对账。
   - **发货**：他自己那页「申请发货」那一栏换成一句说明（后端也会拒绝，防止他从旧链接提交），寄出页的「登记一次发货」客户名单里不会出现他，硬调接口也报「这位客户标了不拼邮」。
   - **货款一分不动**：他买的东西照旧按导入表记在批次里，该收多少日元还是多少，收款、撤销都跟别人一样。
   - **当面交给他之后要能结掉**：客户详情页那一行会出现「这几件已经当面给他了（结掉 N 件）」（`POST /api/admin/customers/:id/received`），点一下这几件直接变「已签收」——不生成寄出记录、不收国内运费。没标不拼邮的客户点这个会被拦住（「拼邮的照旧走称重分摊和寄出」），不能拿它绕过称重。标错了想把物品退回「回国中」，在物品上改状态就行。
   - **不会把账弄悬空**：已经算过运费的摞、还有没处理完的发货申请、已经寄出过的，标的时候会被拦住，要你先「撤销分摊」/处理掉申请/撤销寄出。只是认领了还没算钱的，标的时候会自动退回「未认领」、空出来的那一摞删掉。改回拼邮随时可以：**还没交接的件**重新回到待认领；已经点过「当面给他了」的那些是「已签收」，不会再回这台秤上，也不会再收第二次运费。
   - **秤的口径统一到一处**：认领、逐件称重、整摞称重、标缺件、进度、分摊、以及拆包合包的移动，一律不把「已寄出／已签收」的件算进去（以前称重台还把它们列成「待认领」，点一下报「物品不在此包裹」那种莫名其妙的错）。已签收的件也不算「没寄出」，所以不会挡住整箱「撤销分摊」。
   - **合并客户要两边标记一致**：一个标了不拼邮、一个没标，合完这批货到底走不走我们这条链就说不清了，所以会被拦住，先在详情页把两人改成一样。
   - 数据库层面是 `customers.self_return`（迁移 `0007`，默认 0＝拼邮）。
6. **收款**（后台首页四个待办清单，或客户详情页）：货款按「客户 × 批次」收，国内运费按寄出收。不想一个个客户点确认，就在批次详情页点「这批货款全收」——一次给这批每个还没付的人各记一笔，金额按人分开算好，撤销照旧只退那一个人的那一笔。国际运费同理，在称重台点「这个包裹运费全收」；已经按发货申请逐件收过运费的那一摞不会被重复记，仍走逐件收款。收错了在「收款记录」里撤销，相关的「已付」标记会一起回退。
7. **发货登记**（后台 → 寄出 → 「登记一次发货」，或客户详情页的「可发货」那张卡）：选客户 → 勾这一批要寄的商品 → 填国内快递单号 → 点「标成已发货」。一次点完，这几件同时变「已寄出」、记下发货时间、记一笔国内运费（固定 10 元，「设置」里可改，与件数无关），客户页面立刻显示这个单号并能复制。
   - 快递单号**可以先空着**（东西寄出去了回来再录）：空着生成时不算发货时间，寄出列表上那一条挂橙色「单号待填」，点「补单号」填上就补记发货时间。**之后改单号不会把发货时间挪到改的这一刻**，历史时间不动。
   - 已经被客户申请过发货的那几件在这张单里是**灰的、勾不上**，会写明「已在申请 #N 里，去「发货申请」页寄」——两边都能寄同一件的话会重复寄出，所以只留一条路。
   - 所选物品的国际运费还没付时会**拦截**，并显示「本次应收 = 10 元 + 未付国际运费」，确认「照样发货」后才继续。
   - 撤销在寄出列表上点「撤销」：物品退回「可发货」、这笔国内运费收款一起作废；客户自己申请出来的那一条不许在这里撤销。
8. **找货**（后台右侧那条常驻侧栏）：小票上只看到货号后半截时，在「找货」里输后面几位（比如 `8913` 命中 `ZHOTI678913`），商品名片段、客户名字（含别名）也认。点一条就直接跳到那一件所在的地方——没分摊的在称重台、已分摊的在包裹页、连包裹都没有的在批次页，跳过去后那一件会被框出来并滚到屏幕中间。**站在称重台或包裹页时默认只搜当前这一箱**（一箱几十件，先按人筛比一行行下拉快），这一箱里没有的才回到整库找，结果上会写明它在哪个箱、该去哪一步看。没登录时侧栏不显示；搜索只读数据库，不改动任何东西。

## 图片

**不用花钱开图床。** 页面上的封面图一律引用自己域名下的 `/img/i/{物品ID}`：Worker 按物品 ID 查到真正的图片地址，取回来后放进 Cloudflare 边缘缓存（`caches.default`，缓一周）。好处：

- 国内访问走就近节点，比直连日本图床快；
- 换图床、改地址只动数据库，页面不用改；
- 只代理数据库里存着的地址，不是开放代理（乱传 ID 只会 404）；
- 万一代理不通（对方防盗链之类），浏览器会自动退回直连原地址，再不行才显示「无图」。
- 称重台、批次详情、包裹详情、客户详情的物品列表**都带封面**（图在左、名称在右），旁边一并给出货号；拿不到图的明确显示「无图」，不留空白让人以为漏了。骏河屋的封面是竖图（实测 722×1024），所以框也做成竖的（列表 116×164，称重台再大一档），并且用 `contain` 不裁切——整张图都在，不把局部放大来充数。

直接外链骏河屋的图完全可以，这就是默认走法。唯一要知道的是：**骏河屋是二手单品，卖掉下架后图可能 404**，那件东西就变成占位图 + 名称。拆包认领一般在下单后几周内完成，影响不大；名称、价格、状态都不受影响。

导入时「图片」列的三种情况都认：

1. **单元格里就是图片链接** —— 直接用。
2. **用 `=IMAGE("https://…")` 公式渲染的图**（最常见，Excel 在线版、飞书表格都是这么干的）—— 存成 xlsx 后单元格的值是空的甚至 `#VALUE!`，地址只留在公式里（Excel 里写作 `_xlfn.IMAGE`）。前端解析时会把每个单元格的公式（`cell.f`）和超链接（`cell.l.Target`）里的地址抽出来，和数据一起提交，「图片」「商品链接」两列优先用它。`=HYPERLINK("…","显示文字")`、以及只挂了超链接、本身没文字的空单元格，同样能认出来。
3. **真·嵌在表里的浮动图片** —— SheetJS 社区版取不到，只能靠下面的兜底。

> **下载时要选 .xlsx，别导出 CSV。** CSV 里只有单元格的显示值，`IMAGE()` 公式和超链接都会丢，那样谁也救不回来。

「图片」列整列空着也能有封面：在批次详情页点**「固化封面图」**，服务端按三步补图（一次 20 件，反复点到剩下 0 件为止）：

1. 已经有图片链接的直接用；
2. 没有就去商品链接那一页抓 `og:image`（骏河屋对国外 IP 会回 403，国内直连基本走不通这一步）；
3. 还拿不到就**按货号拼骏河屋官方图片地址** —— 商品链接末尾那串编号小写后套进
   `https://cdn.suruga-ya.jp/database/pics_light/game/{货号}.jpg` 就是这件商品的主图，这个地址国内能直连。
   拼出来的地址一定会先去取一次，**真返回图片才写进数据库**；编号对不上（下架、乱填）就明确留空、显示「无图」，绝不拿别的图凑数。

所以只要表里有「商品链接」这一列，哪怕没有「图片」列，点几次这个按钮封面就都补齐了。货号在页面上也会直接显示出来（批次 / 包裹 / 客户 / 称重台都显示，点一下打开商品页），拆包裹时对着小票上的编号核就行。

### 想让图片永久留在自己手上（可选）

上面的边缘缓存会过期，对方删图之后就真没了。要彻底不怕，就开 R2：

```bash
npx wrangler r2 bucket create surucubby-images   # 需要先在 Cloudflare 账号里开通 R2
# 然后把 wrangler.toml 里 [[r2_buckets]] 那三行的注释去掉，重新 deploy
```

绑了桶之后，「固化封面图」不再只是记一个外链，而是把图片下载进自己的桶，数据库里存成 `/img/{key}`。同一个源地址永远算出同一个 key（源地址 SHA-256 前 32 位 + 扩展名），重复点不会存两份；单张上限 5 MB；返回的不是图片（比如要登录时回的 HTML）会被拒掉并说明原因。R2 有免费额度（10 GB 存储），拼团这点图远用不完，但**开通 R2 需要在账号里绑支付方式**——不想绑就用默认的边缘缓存方案，功能完全够用。

## 分摊算法

```
F      = 这一箱运费总额（分）；不给就用设置里的单价推：round(W × price_fen_per_kg / 1000)，默认 100 元/kg
W      = 这一次进来那些称重组的重量之和（已经算过运费的摞不在里面）
fee_i  = floor(F × w_i / W)          -- 向下取整到分
diff   = F − Σ fee_i                 -- 尾差，累加进 rounding_logs，由需求方承担
```

称重台上**不用手填运费金额**：开始称之前先把这一箱的单价（元 / kg）填进最下面那格，点「存单价」或「算分摊」都会存进 `settings.intl_price_fen_per_kg`，称完点「算分摊」，总额直接由重量 × 单价出来，预览里会写明「¥100.00 / kg × 各摞合计 3,000 g = ¥300.00」；转运仓那天收得不一样，就在预览里把金额改成实收数再确认（改了就不再乘单价）。单价是全箱通用的默认值，每一箱开称前都能改；「设置」页也能改，单价填 0 会被当场拒掉（填 0 等于把一整箱运费静默算成 0 元），拒掉时原来的单价不动。**单价同样封了顶：最多 1000 元 / kg，国内运费最多 1000 元**——这个数要乘进每个人的运费里，手滑多打几个零（哪怕是 9007199254740991 这种看着合法的整数）不报错，但乘出来早就不精确了，整箱分摊的钱全是歪的，所以当场拦住并说明「是不是多打了零」。
分母用各摞重量之和，所以包装箱的重量等于按比例摊给了所有人；尾差不加给任何客户。
**分批分摊**：一笔只算「称好了 + 还没算过运费」的那几摞。按单价算时金额就是这几摞的重量之和 × 单价，所以先算的人不会替后算的人背运费（每一摞摊到的钱和它自己的重量成正比，跟它排第几批算没关系）。手填实收总额 = 转运仓整箱收的那个钱，只有整箱都称完认领完才让填，否则当场拒掉并说还差几摞几件。包裹的总运费、总重量按批次累加，`packages.allocated_at` 一旦写上就代表这一箱至少算过一次。
确认分摊时，每个人这一摞的运费还会拆到**每一件**上：这一摞逐件都称过就按各件轻重拆，只称了整摞就按件数均摊，摞内尾差补给前面几件各 1 分，拆完的和正好等于那一摞的运费（客户是按件勾选申请发货、收款也按件记，所以件上不能留空钱）。这套每件的钱在点「算分摊」时就已定下，「确认分摊」写的是同一份数，不会出现预览一个数、入账另一个数。
整箱到齐时点顶部「整箱全部认领」一次把没认领的归好，不用一件件点封面；已经封账的那几摞不会被塞进新商品（按钮会说明跳过了几件）。
验收用例：3 个客户各 1000 g、总运费 ¥100.00 → 每人 ¥33.33，尾差 ¥0.01；同一样重量按默认单价算是 ¥300.00、每人整 ¥100.00、尾差 0；另一箱 6 件 3 个人、只称整摞（2,000 g / 1,000 g）加一件逐件称（500 g）→ 单价 100 元/kg 时共 ¥350.00，甲那摞 ¥200.00 摊 3 件 = 66.67 + 66.67 + 66.66；还有一箱 5 件 3 个人，只称甲那摞就先算甲（甲 2 件可发货、能申请寄出，乙丙仍「回国中」），再称乙只算乙、包裹总额累加成两次的和，最后全箱弄完才让手填实收（这几条 e2e 都盯着）。

## 实现说明（相对开发方案的补充）

方案里的表都按原样建了，另外加了这些，都是功能必需：

- `items.missing`：称重时「缺件」的标记，缺件不进分摊。
- `payment_items`：一笔货款收款覆盖了哪些物品，撤销收款时按它回退。
- `settings`：全局配置，两把钥匙——`domestic_fee_fen`（国内每次寄出的运费，默认 10 元）、`intl_price_fen_per_kg`（国际运费单价，分/kg，默认 10000 = 100 元/kg）。
- `token_attempts`：客户登录的限流（15 分钟内错 5 次锁 15 分钟），key 按 `qq:<QQ 号>` 记。
- `packages.allocated_at`：这一箱至少算过一次运费（可以只算了几摞），用来显示「已分摊」和允许撤销。挡重复分摊靠 `weigh_groups.intl_fee_fen` 是不是已经有数。
- `items.created_at`：导入时间，方便对账。

其它实现细节：

- **事务**：所有写操作都放在一次 `db.batch()` 里（D1 的 batch 就是一个事务，整批成功或整批回滚）。因为拿不到自增 ID，写入前会先 `SELECT MAX(id)+1` 自己分配主键——这个工具只有一个管理员在用，够了；如果以后要多人同时操作后台，这里要换成真正的序列。
- **导入行数**：一行物品会产生 2 条语句（物品 + 状态日志），一次导入上千行的话建议拆成几张表分批导。
- **包裹批量改状态**只允许 `已下单 / 已到日本仓 / 回国中`（回国中是 `intl_transit`、`cn_arrived` 两个 key 的共同显示名）；「可发货」（`cn_stock`）之后的状态由称重、寄出流程推进，也可以在包裹详情页单件手动改（处理异常）。
- **客户登录 Cookie** 是 HttpOnly 签名 Cookie（里面记着客户 ID 和专属 token），180 天有效；后台「重置链接」之后，旧链接和旧 Cookie 立刻失效。方案里「链接 + 输 QQ 号确认本人」那一步已被新口径覆盖成「QQ 号 + 密码」，QQ 是唯一账号，密码只存哈希。
- 页面上只会出现当前客户自己的数据，接口按会话里的客户 ID 取数，不接受前端传 ID。

## 还没做 / 待确认

方案第 1 节里明确不做的：客户注册登录、在线支付、自动通知、多代购、条码扫描。

方案第 13 节的待确认项，目前的处理方式：

1. ~~**「图片」列是 URL 文本还是嵌在 Excel 里的图片**~~ 已确认：需求方在在线版 Excel 里贴的是图片链接，由 `=IMAGE()` 公式渲染。导入时会从公式和超链接里把地址抽出来（已用真 .xlsx 验证）；默认直接外链 + Worker 边缘缓存，不花钱，见上面「图片」一节。真·嵌入的浮动图片（「置于单元格内」那种）仍然取不到，只能靠 `og:image` 兜底。
2. **金额格式**：`¥`、`￥`、`円`、`元`、千分位、全角数字都能吃下，按「单元格显示值/计算值」读（SheetJS 给什么读什么），四舍五入到分。空金额按 0 元导入并在预览里提醒；看不懂的金额会挡住导入并指出行号。
3. ~~**同一批次里同一个人用两个名字**~~ 已确认做法：「名字 → 客户」只有一份对照表（`customer_aliases`），昵称、旧昵称、表里的各种写法都往里登记。同一个人用两个名字会各自命中同一个客户，欠款不会分家；写法只差空格/全角的自动抹平，真的撞名（好几个人都对得上）不猜，交给你点人。
