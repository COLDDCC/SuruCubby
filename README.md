# SuruCubby · 群友电子仓库

当前流程：日本订单 Excel → 客户仓库 → 拆包/合包并填写回国单号 → 逐件称重、确认运费 → 绿色「已到国内」 → 客户选商品和地址申请发货 → 群主核对扫码转账 → 填写国内快递单号寄出。

## 本次更新与使用规则

- 一张 Excel 按一个日本订单导入；数量拆成独立商品，支持任意购物网站的链接。表头至少有「名称」「客户名字/cn」。
- 「应付人民币金额」是**整行人民币总额**，按数量拆分且保持总额不变。只有「价格/实际价格」时，按**日元单价 × 数量 × 人民币/日元汇率**计算，必须填写汇率并核对预览；金额缺失不再自动当免费。
- 日本订单号、日本物流单号在导入页或批次详情录入。回国单号属于包裹，客户看到自己商品关联的单号，可复制到微信查询。
- 包裹详情勾选商品可移动到另一个未计费包裹或新建包裹，实现拆单/合单。已计费、已申请、已寄出商品不能直接移动，防止账目关联错误。
- 称重台逐件填克数；没有称完的商品必须明确标为缺件。全部算费确认后才显示「已到国内」，不向客户增加到货待称重步骤。
- 客户最多保存3个地址（删除后可重新添加），勾选绿色商品并选择地址提交申请；申请保存当时地址副本。
- 按选中商品收国际运费，每次申请国内运费使用后台设置（默认10元）；线上不接支付。群主在「发货申请」核对扫码转账后确认收款，再填写单号寄出。
- 收款错误可在收款记录撤销；国内申请款撤销后退回待收款，国际款撤销后必须重新确认收款才能寄出。已寄出的申请保留历史，不允许直接撤销物流。
- 合并客户：有冲突的已计费称重组时禁止合并，先撤销相关收款和分摊。其他未计费数据可合并；地址合计超过3个时先整理地址。
- 修改管理员密码会让旧管理员登录失效。后台密码输错5次锁15分钟；写操作串行保护，多窗口同时保存时提示重试。

## 更新已有部署

先备份数据库，执行 `npm run db:remote` 应用 `0002_workflow.sql`，再 `npm run deploy`。新安装也必须先建库并应用全部迁移。此仓库的 D1 ID 仍是占位符，未自动部署到生产环境。

旧版按客户整摞称重生成的账目保留查看；若需要客户逐件申请发货，先在未收款、未寄出的条件下撤销旧分摊，再逐件填重量重新确认，不能直接猜每件重量。

## 技术栈

| 部分 | 选择 |
|---|---|
| 运行环境 | Cloudflare Workers + 静态资源 |
| 后端 | Hono |
| 数据库 | Cloudflare D1（SQLite） |
| Excel 解析 | 浏览器端 SheetJS，解析成 JSON 再提交，Worker 不碰二进制 |
| 前端 | 原生 HTML/ES Module，手机优先，无构建步骤 |

硬性约定：**金额一律用整数「分」存**，日元用整数「円」存；时间存 UTC，页面按北京时间显示。

## 本地跑起来

```bash
npm install
cp .dev.vars.example .dev.vars     # 填上 ADMIN_PASSWORD 和 SESSION_SECRET
npm run db:local                   # 建本地库表
npm run dev                        # http://127.0.0.1:8787
```

打开 <http://127.0.0.1:8787/admin/>，用 `.dev.vars` 里的密码登录。

## 部署到 Cloudflare

```bash
npm install
npx wrangler login                          # 浏览器里授权一次 Cloudflare 账号

npx wrangler d1 create surucubby            # 把返回的 database_id 填进 wrangler.toml
npm run db:remote                           # 在线上库建表
npm run deploy                              # 先部署，Worker 才存在

npx wrangler secret put ADMIN_PASSWORD      # 后台密码
npx wrangler secret put SESSION_SECRET      # Cookie 签名密钥，随便一串长随机字符串
```

密码和密钥设好就立刻生效，不用再 deploy 一次。以后改代码只要 `npm run deploy`。

部署完**务必绑定自己的域名**（Workers 控制台 → 该 Worker → Settings → Domains & Routes）。
`*.workers.dev` 在国内经常打不开。

图片不用另外开图床，默认就能跑，见下面「图片」一节。

可选但国内建议做：把 SheetJS 自托管到 `public/vendor/xlsx.full.min.js`，见 [`public/vendor/README.md`](public/vendor/README.md)。没有这份文件时导入页会回退到官方 CDN。

## 日常怎么用

1. **导入**（后台 → 导入）：选 Excel → 填批次名 → 看预览。
   - 表头按文字定位，必须有「名称 / cn / 应付人民币金额」，可选「图片 / 商品链接 / 平时价格 / 实际价格」。
   - `cn` 的名字在别名表里查得到就自动认人；查不到的行**标黄**，要么选一个已有客户（等于给他加个别名），要么填 QQ 号新建客户。黄行没处理完不给导。
   - 同一个文件（内容哈希相同）导过会提示，勾了确认才放行。
   - 导入时自动建一个同名包裹，这一批的物品都挂在上面，状态 `已下单`。
   - 图片列可以是图片链接，也可以是 `=IMAGE("https://…")` 这种公式（Excel 在线版、飞书表格都会存成公式，见下面「图片」一节）。
   - 新建的客户会把专属链接一次性列出来，复制到群里发给本人。
2. **改状态**（后台 → 包裹）：下拉改包裹状态，包裹内物品同步变更。
   已取消 / 已退款、以及已经进入国内在库之后的物品不受影响。
3. **称重**（后台 → 包裹 → 称重台，手机上用）：
   - 顶部常驻「应有 N 件 / 已找到 M 件」「已称 X 人 / 共 Y 人」。
   - 拿起一件点它的封面就算「已找到」；找不到的点「缺件」写说明，缺件不参与分摊。
   - 某人的东西找齐后，堆成一摞称重量（克）填进去。
   - 全部称完后填这个包裹的**实际国际运费**（可选填转运仓给的总重量），点「计算分摊」看预览再确认。
   - 确认后这些物品变成「国内在库」。没人付过这个包裹运费之前，可以「撤销分摊」重来。
4. **收款**（后台首页四个待办清单，或客户详情页）：货款按「客户 × 批次」收，也能只勾一部分；国际运费按称重组收；国内运费按寄出收。收错了在「收款记录」里撤销，相关的「已付」标记会一起回退。
5. **寄出**（后台 → 客户详情 → 国内在库）：勾物品 → 生成一次寄出 → 填国内单号。每次固定收 10 元（「设置」里可改），与件数无关。所选物品的国际运费还没付时会**拦截**，并显示「本次应收 = 10 元 + 未付国际运费」，确认后可以强制继续。

## 图片

**不用花钱开图床。** 页面上的封面图一律引用自己域名下的 `/img/i/{物品ID}`：Worker 按物品 ID 查到真正的图片地址，取回来后放进 Cloudflare 边缘缓存（`caches.default`，缓一周）。好处：

- 国内访问走就近节点，比直连日本图床快；
- 换图床、改地址只动数据库，页面不用改；
- 只代理数据库里存着的地址，不是开放代理（乱传 ID 只会 404）；
- 万一代理不通（对方防盗链之类），浏览器会自动退回直连原地址，再不行才显示「无图」。

直接外链骏河屋的图完全可以，这就是默认走法。唯一要知道的是：**骏河屋是二手单品，卖掉下架后图可能 404**，那件东西就变成占位图 + 名称。拆包认领一般在下单后几周内完成，影响不大；名称、价格、状态都不受影响。

导入时「图片」列的三种情况都认：

1. **单元格里就是图片链接** —— 直接用。
2. **用 `=IMAGE("https://…")` 公式渲染的图**（最常见，Excel 在线版、飞书表格都是这么干的）—— 存成 xlsx 后单元格的值是空的甚至 `#VALUE!`，地址只留在公式里（Excel 里写作 `_xlfn.IMAGE`）。前端解析时会把每个单元格的公式（`cell.f`）和超链接（`cell.l.Target`）里的地址抽出来，和数据一起提交，「图片」「商品链接」两列优先用它。`=HYPERLINK("…","显示文字")`、以及只挂了超链接、本身没文字的空单元格，同样能认出来。
3. **真·嵌在表里的浮动图片** —— SheetJS 社区版取不到，只能靠下面的兜底。

> **下载时要选 .xlsx，别导出 CSV。** CSV 里只有单元格的显示值，`IMAGE()` 公式和超链接都会丢，那样谁也救不回来。

压根没有图片地址的物品，在批次详情页点「固化封面图」，服务端会去商品链接那一页抓 `og:image` 补上（一次 20 件，可以反复点到 `left` 为 0）。

### 想让图片永久留在自己手上（可选）

上面的边缘缓存会过期，对方删图之后就真没了。要彻底不怕，就开 R2：

```bash
npx wrangler r2 bucket create surucubby-images   # 需要先在 Cloudflare 账号里开通 R2
# 然后把 wrangler.toml 里 [[r2_buckets]] 那三行的注释去掉，重新 deploy
```

绑了桶之后，「固化封面图」不再只是记一个外链，而是把图片下载进自己的桶，数据库里存成 `/img/{key}`。同一个源地址永远算出同一个 key（源地址 SHA-256 前 32 位 + 扩展名），重复点不会存两份；单张上限 5 MB；返回的不是图片（比如要登录时回的 HTML）会被拒掉并说明原因。R2 有免费额度（10 GB 存储），拼团这点图远用不完，但**开通 R2 需要在账号里绑支付方式**——不想绑就用默认的边缘缓存方案，功能完全够用。

## 分摊算法

```
W      = 该包裹所有称重组的重量之和
fee_i  = floor(F × w_i / W)          -- 向下取整到分
diff   = F − Σ fee_i                 -- 尾差，记在 rounding_logs，由需求方承担
```

分母用各摞重量之和，所以包装箱的重量等于按比例摊给了所有人；尾差不加给任何客户。
验收用例：3 个客户各 1000 g、总运费 ¥100.00 → 每人 ¥33.33，尾差 ¥0.01。

## 实现说明（相对开发方案的补充）

方案里的表都按原样建了，另外加了这些，都是功能必需：

- `items.missing`：称重时「缺件」的标记，缺件不进分摊。
- `payment_items`：一笔货款收款覆盖了哪些物品，撤销收款时按它回退。
- `settings`：全局配置，目前只有 `domestic_fee_fen`（国内每次寄出的运费）。
- `token_attempts`：客户页 QQ 校验的限流（15 分钟内错 5 次锁 15 分钟）。
- `packages.allocated_at`：这个包裹是否已经分摊过，用来挡住重复分摊、允许撤销。
- `items.created_at`：导入时间，方便对账。

其它实现细节：

- **事务**：所有写操作都放在一次 `db.batch()` 里（D1 的 batch 就是一个事务，整批成功或整批回滚）。因为拿不到自增 ID，写入前会先 `SELECT MAX(id)+1` 自己分配主键——这个工具只有一个管理员在用，够了；如果以后要多人同时操作后台，这里要换成真正的序列。
- **导入行数**：一行物品会产生 2 条语句（物品 + 状态日志），一次导入上千行的话建议拆成几张表分批导。
- **包裹批量改状态**只允许 `已下单 / 已到日本仓 / 国际运输中 / 已到国内待称重` 四个；国内在库之后的状态由称重、寄出流程推进，也可以在包裹详情页单件手动改（处理异常）。
- **客户页 Cookie** 是 HttpOnly 签名 Cookie，180 天有效；后台「重置链接」之后，旧链接和旧 Cookie 立刻失效。
- 页面上只会出现当前客户自己的数据，接口按 token 对应的客户 ID 取数，不接受前端传 ID。

## 还没做 / 待确认

方案第 1 节里明确不做的：客户注册登录、在线支付、自动通知、多代购、条码扫描。

方案第 13 节的待确认项，目前的处理方式：

1. ~~**「图片」列是 URL 文本还是嵌在 Excel 里的图片**~~ 已确认：需求方在在线版 Excel 里贴的是图片链接，由 `=IMAGE()` 公式渲染。导入时会从公式和超链接里把地址抽出来（已用真 .xlsx 验证）；默认直接外链 + Worker 边缘缓存，不花钱，见上面「图片」一节。真·嵌入的浮动图片（「置于单元格内」那种）仍然取不到，只能靠 `og:image` 兜底。
2. **金额格式**：`¥`、`￥`、`円`、`元`、千分位、全角数字都能吃下，按「单元格显示值/计算值」读（SheetJS 给什么读什么），四舍五入到分。空金额按 0 元导入并在预览里提醒；看不懂的金额会挡住导入并指出行号。
3. **同一批次里同一个人用两个名字**：别名机制已经能处理（两个名字都会映射到同一个客户），预览里会各占一行，分别指认即可。
