# SuruCubby 界面改版方案（v2）

> 来源：另一位 agent 推荐的「方案 B：shadcn 视觉 + Tabler 组件 + AfterShip 团员端 + ShipBob 仓库端 + 17TRACK 时间线」。
> 本文件先评估这份推荐，再给出落地方案和逐文件改动清单。改动已按本方案实现，见文末「实施记录」。

---

## 0. 结论先说

**方向我同意 B**：后台要专业、团员端要像物流查询页、仓库端要像拣货终端，三端共用一个品牌。
**但执行方式我不同意「直接引入 Tabler / shadcn 代码」**，理由见第 1 节。我的做法是：

1. **只借设计，不借依赖**：把 shadcn 的视觉规则（中性灰底、1px 细边、8–10px 圆角、克制的阴影、紧凑间距）和 Tabler 的布局模式（左侧分组导航、页头、KPI 卡、状态点徽章、竖向时间线、步骤条）**用现有类名重写进 `public/style.css`**。不加 Bootstrap、不加 Tailwind、不加构建步骤。
2. **先修功能上的错位，再换皮**：看代码发现后台首页「待办」还停在**旧流程**（国际运费 / 国内运费 / 可发货），新流程里群主每天真正要做的「放行」「单号放行」一条都不在首页。换皮不解决这个问题，所以这次一起改。
3. **团员端做成真正的「物流查询页」**：顶部一条按件数走的进度管线，直邮包裹做成运单卡（单号大字 + 步骤条 + 平铺图），动态从表格改成竖向时间线。
4. **仓库端保留大图分拣**（同意原方案），补上进度条、手机底部常驻操作按钮、更大的扫码/输入框。

## 1. 对原推荐的评估

| 推荐 | 能不能直接用 | 我的处理 |
|---|---|---|
| **Tabler（MIT，Bootstrap 5）** | 不建议整包引入。① Bootstrap 的 `.row` 是带负边距的栅格，我们全站 200+ 处 `.row` 是 flex 横排，一引入就全乱；`.card`、`.badge`、`.btn`、`.small`、`.muted` 同样撞名。② 压缩后 CSS 约 200 KB + 图标字体，而现在整站 CSS 只有 ~20 KB；国内手机 QQ 浏览器上首屏会明显变慢。③ 部署说明里刻意「页面不加载境外资源」，引入还得自托管。 | 只借**布局模式**：左侧分组导航、page header、KPI 卡、带圆点的状态徽章、竖向时间线、步骤条。自己写 CSS，名字跟现有类一致。 |
| **shadcn-admin（MIT，React + Tailwind）** | 代码**完全不能复用**：我们是原生 ES Module、无构建，React 组件搬不过来。 | 只借**视觉规则**：设计 token（颜色、圆角、阴影、间距、字号阶梯），写进 `:root` 变量。 |
| **AfterShip Tracking（商业）** | 只能借鉴布局，不复制素材。 | 团员页：首屏「现在到哪了」一句话 + 进度管线；运单卡。 |
| **17TRACK（商业）** | 同上。 | 运单卡里的步骤条、「最近动态」竖向时间线。 |
| **ShipBob WMS（商业）** | 同上。 | 仓库端：每个客户卡上的进度条、首页大号单号输入、底部常驻主按钮。 |
| `npx skills add tabler/tabler` | 不需要：我们不用 Tabler 的类名，装了反而会让 agent 往页面里写 Bootstrap 类。 | 不装。 |

**三个硬约束不变**（README 里写着的）：手机优先、无构建步骤、不加载境外资源。深色模式的 WCAG AA 对比度要求继续遵守。

| 状态 | 色调 | 徽章 |

| 已下单 / 已到日本仓 | 中性灰 | `badge dot` |

| 已打包 | warn 琥珀 | `badge warn dot` |
| 回国中 | violet 紫 | `badge violet dot` |
| 可发货 / 已寄出 / 已签收 | ok 绿 | `badge ok dot` |
| 缺货取消 / 已退款 | danger 红 | `badge danger dot` |

`.badge.dot` 在文字前加一个 6px 圆点（Tabler 的 status-dot 做法），只用颜色以外还有文字，色弱也能读。

## 3. 后台（群主）

### 3.1 外壳：顶栏 → 左侧分组导航

现在 9 个入口挤在一条顶栏，其中「包裹」「寄出」已经是旧流程，新流程的「直邮包裹」反而排在后面。

- **≥ 1024px**：左侧 232px 深海军蓝侧栏，分组：
  - **日常**：待办 · 导入 · 订单 · 客户 · 直邮包裹
  - **账目**：收款
  - **系统**：设置
  - **旧流程**（小号灰字分组）：包裹 · 寄出
  - 底部：退出
- **< 1024px**：侧栏收成现在这样的顶栏 + 横滑导航（分组标题隐藏），手机操作习惯不变。
- 找货侧栏（`#rail`）位置不变：宽屏贴右，窄屏在内容上方。
- **兼容性**：`#nav`、`#nav a[href]`、`#logout`、`#view`、`#rail` 这些 id 和结构全部保留，`app.js` 的 `markNav()` 不用改。

### 3.2 首页「待办」改成新流程（功能修正，含后端）

`GET /api/admin/dashboard` **只加字段不删字段**：

| 新字段 | 查询 | 首页怎么用 |
|---|---|---|
| `toRelease` | `items.released_at IS NULL` 且非取消/退款，按「订单 × 客户」分组，带件数、货款、是否已付 | **① 待放行**：每行一个「放进他的仓库」按钮（调现有 `POST /api/admin/quick-order/release`），已收货款的排前面 |
| `parcelsPending` | `parcels.released_at IS NULL`，带客户、提交日、毛重、应收（按 `sale_fen_per_kg` 算） | **② 等单号放行的直邮包裹**：按提交日分组，链接到「直邮包裹」页对应日期 |
| `whBacklog` | 已放行、`sorted_at IS NULL`、状态还在已下单 / 已到日本仓，按订单分组 | **③ 仓库还没整理**：只读，让群主知道卡在哪一单 |
| `openBoxes` | `packages.kind='group' AND returned_at IS NULL`，带件数和回国单号填没填 | **④ 拼邮箱还没发出** |
| `goodsUnpaid`（已有） | | **⑤ 货款未收**，逻辑不变 |
| `intlUnpaid` / `domesticUnpaid` / `domesticStock` / `pendingRefunds`（已有） | | 有数据才显示，收进「旧流程 / 其他」折叠区 |

顶部一排 KPI：**待放行 N 人 · 等放行包裹 N 个 · 货款未收 X 円 · 仓库未整理 N 件**。每个 KPI 可点击跳到下面对应清单。

### 3.3 订单详情

- 表格封面从 116×164 收到 64×92（`.cell-thumb.sm`）：这一页是群主核账用的，不是对货用的；一单 30 个人时整页能少滚 60%。称重台、包裹页的大图**不动**。
- 每位客户的卡头改成 `.card-head`：左边「名字 · QQ · 件数 · 直邮/拼邮 · 仓库整理进度」，右边「合计 / 未付」和「放行」按钮。
- 状态列改用统一状态徽章。

### 3.4 订单列表

- 页头 `.page-head`（标题 + 「录入新订单」按钮）。
- 筛选按钮做成 `.segmented` 风格的胶囊组。
- 进度条沿用现有 `.order-bar`，颜色换成新的状态色映射。

## 4. 团员端（AfterShip / 17TRACK 风格）

### 4.1 首屏

```
┌──────────────────────────────────────┐
│ 小鱼 的仓库        [直邮]   退出登录 │
│ 仓库已经分拣好 3 件，下一步打包直邮… │  ← 现在到哪了，一句话（大字）
│                                      │
│ ●──────●──────○──────○               │  ← 进度管线：每一步下面写件数
│ 已下单  已分拣  已打包  已寄出        │     (拼邮第三步是「回国中」)
│  1件    3件     0       0            │
├──────────────────────────────────────┤
│ 货款待付 10,400円 │ 等付运费 0 个包裹 │  ← 只留两个跟钱有关的数
└──────────────────────────────────────┘
```

- 管线的「点亮」规则：某一步及之后还有件数，这一步就算点亮；当前件数最多的那一步加粗为「现在」。纯前端由 `items` 计算，不改接口。
- 原来四个 KPI 里「已分拣」「已寄出」已经在管线里，首屏只保留「货款待付」「等付运费的包裹」两个钱的数。

### 4.2 直邮运单卡

- 放行前：琥珀色边，「仓库已经打好包 · N 件」+ 两步步骤条（已打包 ● → 已寄出 ○）+ 说明 + 商品小图条。
- 放行后：单号用面单式大号等宽字 + 「复制单号」，步骤条两步都亮，下方 kv（毛重、运费、件数），平铺图网格，商品清单带小图和来源订单号胶囊。

### 4.3 商品卡与动态

- 商品卡：状态徽章走统一状态色；「货款未付」保持红色。
- 「最近动态」：表格 → 竖向时间线（时间小字 + 圆点 + 商品名 + 新状态徽章），手机上不再被三列挤成一字一行。

## 5. 仓库端（ShipBob 风格，保留大图）

- **首页**：单号输入框加大成一张「扫码 / 输单号」主卡；最近订单每行带整理进度条。
- **订单操作台**：客户芯片里加进度条（已整理/总数），完成的变绿色实边而不是虚线（虚线看起来像「未完成」）。
- **手机底部操作条**：「整理完成」「提交包裹（N 件）」在 ≤ 640px 时贴底常驻（`.actionbar`，带 `safe-area-inset-bottom`），一边翻图一边能按。
- 直邮包裹卡、拼邮箱列表：用 `.card-head` 统一标题行。
- 仓库接口和页面依旧**不出现任何价格**；本次只改样式和结构，不动 `/api/wh/*`。

## 6. 首页（选身份）

- 三种身份改成 `.segmented` 分段切换（团员 / 群主 / 仓库），仓库那一格仍是链接。
- hero 加一层很淡的风线渐变背景，保留「车开进来」的唯一动画和 `prefers-reduced-motion`。
- `entry.js` 只把 `className` 切换换成 `aria-pressed` + `.on`，逻辑不动。

## 7. 不做的事（以及为什么）

- **不引入任何 CSS/JS 框架**：理由见第 1 节。
- **不改任何业务规则和权限边界**：谁看得到什么那张表一个格都不动；后端只给首页加只读查询。
- **不重写旧流程页面**（称重台、寄出、发货申请）：它们已经不在主流程上，跟着新 token 自动换色即可。
- **不做图标字体**：中文标签已经够清楚，加图标要么引外部资源，要么塞一堆 SVG，收益不大。以后要加，建议用内联 SVG sprite（Tabler Icons 也是 MIT，可以挑十几个自托管）。

## 实施记录

按上面的清单全部做完，另外顺手修了两处：

- **订单列表进度条漏了新流程的两段**：`batches.js` 的 `STAGES` 里没有「已分拣」「已打包」，新流程的订单进度条上这两段一直算不进去。已补上（分拣蓝、打包琥珀、回国紫）。
- **清单太长时折叠**：首页每个清单、团员页「最近动态」只露前几条，其余收进「再看 N 条」。

验证：

- `npm test`：47 通过 / 1 跳过（与改版前一致）
- e2e（隔离实例）：64 / 64 通过；`warehouse.e2e.test.mjs` 在原有流程的四个节点上补了首页断言：未放行 → 出现在 `toRelease`；放行后 → 挪到 `whBacklog`；打包未放行 → 出现在 `parcelsPending`（只有售价，不带仓库价）；单号放行后 → 从 `parcelsPending` 消失
- 三端 × 桌面 390/1366 × 浅色/深色截图逐页过了一遍

还可以继续做的（这次没做）：

- 客户详情、直邮包裹、设置、导入几个后台页换成 `.page-head` 页头（现在它们自动吃到新 token，只是还没有统一页头）
- 内联 SVG 图标（Tabler Icons，MIT，自托管十几个即可）
- 首页「待放行」支持勾选后批量放行
